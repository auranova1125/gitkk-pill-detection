# 탐지 데이터 구성 및 입력 검증 보고서

## 1. 목적

검증된 SELECT·대회 데이터를 통합하고, 공통 Train/Validation 분할을 사용하는 단일 클래스 알약 탐지용 DataLoader를 구성하였다.

모든 알약의 탐지 정답은 `pill=1`이며, 원본 약품 코드는 추적과 분류기 연결을 위해 보존한다.

## 2. 최종 데이터

| 항목 | Train | Validation | 전체 |
|---|---:|---:|---:|
| 이미지 수 | 8,256장 | 2,063장 | 10,319장 |
| 박스 수 | 31,673개 | 7,915개 | 39,588개 |
| 조합 그룹 수 | 2,870개 | 717개 | 3,587개 |
| 빈 이미지 수 | 0장 | 0장 | 0장 |
| 이미지당 최대 박스 수 | 4개 | 4개 | 4개 |

- 원본 약품 클래스는 양쪽 모두 118종이다.
- 탐지 foreground 클래스는 `pill` 1종이다.
- background를 포함한 모델 클래스 수는 2이다.
- Train과 Validation 사이의 조합 그룹 중복은 0개이다.
- 경계 보정이 필요한 박스는 0개이다.

## 3. 데이터 선정 및 분할 기준

- SELECT와 대회 Train을 검증하고 오류 이미지는 수정 없이 제외하였다.
- 이미지 단위로 제외하며, 해당 이미지의 모든 annotation을 함께 제거하였다.
- 추가로 확인한 오류 이미지 5장도 같은 방식으로 제외하였다.
- 추가 제외 시 나머지 이미지의 분할 배정과 ID는 유지하였다.
- 파일명의 알약 코드 조합을 그룹으로 사용하였다.
- 같은 조합의 촬영 이미지는 한쪽 분할에만 배정하였다.
- 최초 분할은 목표 비율 80:20, seed 42로 구성하였다.
- 담당자별 모델 비교를 위해 공통 분할을 유지한다.

제외 이미지 집계는 SELECT 136장, 대회 17장이다. 원본 이미지 파일의 보관 여부와 실제 학습 대상 포함 여부는 구분하며, 학습 대상은 최종 라벨과 분할 목록으로 결정한다.

## 4. 입력 구성

| 항목 | 처리 |
|---|---|
| 이미지 | RGB, CPU, float32, `[3,H,W]`, 값 범위 0~1 |
| 원본 bbox | XYWH |
| target bbox | XYXY |
| target label | 모든 알약에 대해 정수 1 |
| target area | 경계 처리·변환 후 bbox에서 재계산 |
| iscrowd | 정수 0 |
| 배치 | `images`, `targets`, `meta` 각각 리스트 |
| 원본 약품 코드 | `meta`에 보존 |
| 현재 학습 증강 | 적용하지 않음 |
| Validation 무작위 변환 | 적용하지 않음 |
| 외부 resize·ImageNet 정규화 | 적용하지 않음 |

이번 검증은 MPS 환경에서 batch size 8, num_workers 0, pin_memory False로 실행하였다.

## 5. 검증 결과

### 전체 라벨 및 분할 구조

- 최종 이미지·annotation 수가 기준 집계와 일치하였다.
- 전체 이미지 파일 경로가 존재함을 확인하였다.
- 이미지 및 annotation ID 중복이 없음을 확인하였다.
- annotation과 이미지 ID의 연결을 확인하였다.
- 분할 목록과 학습용 JSON이 일치하였다.
- Train/Validation의 조합 그룹 중복이 없었다.
- 전체 bbox의 유효한 수치·양의 크기 및 경계 처리 결과를 확인하였다.
- annotation 개수가 변환 과정에서 누락되지 않도록 구성하였다.

### 팀원의 실제 입력 검증 함수

다음 함수 실행이 통과하였다.

- `validate_detector_label_map`
- `validate_detector_data_summary`
- Train 첫 배치의 `validate_detection_batch`
- Validation 첫 배치의 `validate_detection_batch`

각 첫 배치에는 이미지 8장이 포함되었다. 검증 후 학습에 사용할 로더를 다시 생성하였다.

### GitHub용 코드 연결

새 함수 경로를 사용하여 같은 검증을 실행하였다.

```text
detector_data.detector_inputs:build_detector_inputs
```

공유 패키지와 데이터 집계·클래스 매핑이 일치하고, Train·Validation 첫 배치 검증이 통과하였다.

## 6. 표본 시각 검토

| 분할 | 출처 | 이미지 ID | 박스 수 |
|---|---|---:|---:|
| Train | SELECT | 4 | 4 |
| Train | 대회 | 10113 | 4 |
| Validation | SELECT | 1 | 4 |
| Validation | 대회 | 10110 | 4 |

표본 4장에서 알약마다 박스가 하나씩 있고, 박스가 알약을 감싸는 것을 확인하였다. 탐지 라벨은 모두 1이었다.

이는 전체 이미지의 시각 검토가 완료됐다는 의미는 아니다.

## 7. 데이터 식별값

```text
992d7f0416335b49891640b257cb4c2f3a82a9faa6c14cfce32391861a606010
```

위 `split_hash`는 데이터 구성 코드에서 분할·이미지·annotation·bbox 등의 기록을 직렬화하여 계산한 값이다.

공유 패키지와 GitHub용 코드에서 동일한 값을 확인하였다. 다른 구현의 해시는 계산 방식이 다를 수 있으므로 값만으로 직접 비교하지 않는다.

## 8. 확인 범위와 한계

- 현재는 전달받은 단일 클래스 SSDLite 입력 명세를 기준으로 검증하였다.
- 다른 탐지 모델과의 입력·학습 코드 호환성은 별도로 확인해야 한다.
- 전체 이미지의 픽셀을 DataLoader로 반복 순회하는 검사는 이번 연결 단계에서 수행하지 않았다.
- 첫 배치 검증과 표본 시각 검토가 전체 annotation의 정확성을 보장하지 않는다.
- 모델 생성, 순전파, 역전파 및 실제 학습은 아직 검증하지 않았다.

다음 확인 단계는 담당 모델에서 첫 배치의 손실 계산·역전파·가중치 갱신을 수행하는 짧은 학습 테스트이다.
