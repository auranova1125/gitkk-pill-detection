# train/val 분할 결과 (분류기 crop)

`python -m etl.classifier.assign_data_splits` 결과 (2026-10-28). `data/classifier/crops/crops.csv`의 `split` 열 기준이다.

## 분할 기준

- 탐지기 학습 패키지 `training_package_detector.zip`의 `split_manifest.csv`를 그대로 따른다.
- 그룹 = 파일명의 알약 코드 조합 (예: `K-001900-016548-019607-029451`). 같은 그룹은 탐지기와 같은 쪽(train 또는 val)에 넣는다.
- 탐지기 목록에 없는 그룹은 train에 넣는다. 그래서 분류기 val은 모두 탐지기 validation 그룹 안에 있다.

## 요약

| 항목 | train | val |
|---|---:|---:|
| **crop** | **12,125** | **2,863** (19.1%) |
| └ AI Hub 조합 | 11,571 | 2,661 |
| └ Kaggle | 554 | 202 |
| 그룹 | 1,786 | 429 |
| 클래스별 최소 / 중앙값 / 최대 | 33 / 90 / 373 | 9 / 22 / 110 |

| 확인 | 결과 |
|---|---|
| train/val 양쪽에 걸친 그룹 | 0개 |
| val이 없는 클래스 | 0종 |
| 클래스별 val 비율 | 8.3% ~ 26.9% (중앙값 19.4%) |
| 탐지기 목록에 없어 train에 넣은 그룹 | 9개 (crop 37개) |
| 그룹은 다르지만 거의 같은 사진(pHash 거리 ≤ 5)이 train/val에 나뉜 쌍 | 379쌍 |
| train에 거의 같은 사진이 있는 val 이미지 | 219장 / 776장 (crop 799개) |

거의 같은 사진은 대부분 알약 하나만 다른 조합이다 (나머지 알약은 같은 실물, 같은 자리). 탐지기 분할에도 똑같이 있으며, 이 val crop은 점수가 실제보다 높게 나올 수 있다.

`crops.csv`의 `near_dup_in_train` 열이 True인 crop이 이 799개다. 분류기를 평가할 때 **전체 val(2,863개)**과 **이 열이 False인 val(2,064개)** 점수를 함께 본다. 차이가 크면 train 사진을 외워서 맞힌 몫이 크다는 뜻이다.

```python
df = pd.read_csv(CROPS / "crops.csv")
val_all = df[df.split == "val"]
val_clean = val_all[~val_all.near_dup_in_train]
```
