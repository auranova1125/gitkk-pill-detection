## 1. 왜 다시 검수했나

기준 모델 `resnet50_baseline_v1`(#14)의 val 오분류 5건을 원본 사진에서 확인했더니 모두 데이터 오류였다.

| 사진 | 오류 |
| --- | --- |
| Kaggle `K-003483-025367-027733-035206_..._75` | 트윈스타정 ↔ 아토젯정 라벨이 서로 바뀜 (2건) |
| AI Hub `K-010224-016548-033009-033878_..._70` | 넥시움정 bbox가 신바로정 위에 있음 |
| AI Hub `K-016235-019861-020238-031885_..._90` | 카듀엣정 bbox가 빈 배경에 있음 |
| AI Hub `K-006835-020004-024941-029711_..._90` | 액티프롤정 bbox가 다른 알약 가장자리에 있음 |

1차 검수(`validate_labels.py`, [`validation_report.md`](validation_report.md))는 bbox 값(크기, 범위, 겹침 IoU 0.7 이상 등)만 보므로, 엉뚱한 곳에 그려진 bbox와 바뀐 이름표를 잡지 못한다. val에 있는 오류는 train에도 있을 수 있고, 같은 사진이 탐지기 학습에도 쓰인다.

## 2. 방법

오류를 두 종류로 나눠 찾는다. 두 검사 모두 **코드가 의심 후보를 고르고, 사람이 사진을 보고 판정**한다. 코드는 알약 영역을 잘못 찾는 경우(오탐)가 있어 코드 결과만으로 빼지 않는다.

| 검사 | 찾는 오류 | 방법 |
| --- | --- | --- |
| 위치 검수 | bbox가 알약과 안 맞음 (빈 배경, 다른 알약 위, 밀림, 잘림) | 사진에서 알약 영역을 찾아 bbox와 1:1로 짝 맞춤 |
| 클래스 검수 | 위치는 맞는데 이름표가 틀림 | 기준 모델 `best.pt`의 embedding으로 생김새 비교 |

### 2-1. 위치 검수 (`audit_bbox_position.py`)

1. 배경: 조명 그라데이션이 있으므로 Lab 색을 2차 곡면으로 맞춘다
2. 알약 영역: 배경과 색이 다른 픽셀 + 윤곽선(배경과 색이 비슷한 파란·회색 알약용). 잡티와 사진 모서리 비네팅은 뺀다
3. 알약 영역과 bbox를 IoU로 1:1 짝 맞춤 (헝가리안)

| 점수 | 뜻 |
| --- | --- |
| `match_iou` | 짝이 된 알약 영역과의 IoU. 0이면 짝 없음 |
| `fg_in` | bbox 안의 알약 영역 비율. 0에 가까우면 빈 배경 |
| `ring_fg` | bbox를 8% 넓힌 바깥 띠의 알약 영역 비율. 높으면 잘림 |
| `unmatched_blobs` | 사진에서 bbox와 짝이 안 된 알약 영역 수 |

| 의심 등급 | 기준 |
| --- | --- |
| 1 강함 | `fg_in` < 0.15, 0 < `match_iou` < 0.5, 짝 없음 + bbox 없는 알약 있음, 짝 없음 + bbox 안 절반 이상 배경 |
| 2 약함 | 짝 없음이지만 bbox 안이 알약으로 차 있음 (붙은 알약이 한 덩어리로 잡힌 경우가 많음) |
| 3 경계 | 0.5 ≤ `match_iou` < 0.6 |

### 2-2. 클래스 검수 (`audit_class_label.py`)

1. `best.pt`로 모든 crop의 embedding(2048차원)을 구한다. 전처리는 학습의 val과 같다
2. **같은 그룹 비교**: 같은 조합 그룹은 같은 실물 알약을 각도만 바꿔 찍었다. 다른 각도 사진에서 같은 클래스보다 다른 클래스와 더 닮았으면 의심
3. **교차 검증 예측**: 그룹 단위 5-fold로 embedding 위에 로지스틱 회귀를 학습해, 학습에 안 쓴 crop의 클래스를 예측한다. `best.pt`는 train 라벨을 이미 학습해서 train의 틀린 라벨도 외웠을 수 있기 때문이다
4. **서로 바뀜**: 같은 사진의 두 crop이 서로 상대 클래스로 판단되면 swap

| 의심 등급 | 기준 |
| --- | --- |
| 1 강함 | swap, 또는 같은 그룹 비교와 교차 검증이 둘 다 다른 클래스를 가리킴 |
| 2 약함 | 둘 중 하나만 다른 클래스를 가리킴 |

### 2-3. 사람 판정 기준

| 판정 | 기준 |
| --- | --- |
| 오류 | bbox 안에 알약이 없음 / 다른 알약 위에 있음 / 알약 일부가 bbox 밖으로 잘림 / bbox가 알약보다 지나치게 큼 / 다른 품목 |
| 정상 | 알약이 bbox에 맞게 들어 있음. 아주 조금 벗어난 정도는 정상 |

검수 그림은 `data/classifier/meta/label_audit/review/`에 있다. 위치 검수는 `p<등급>_review_<번호>.jpg`, 클래스 검수는 `c<등급>_review_<번호>.jpg`이고, CSV의 `그림번호`가 그림의 번호다.

### 2-4. 조치 규칙

1차 검수와 같은 원칙을 따른다.

| 출처 | 조치 | 이유 |
| --- | --- | --- |
| AI Hub 조합 사진 | 이미지 제외 | 대신 쓸 사진이 많다 |
| Kaggle | bbox 제외 | 대신할 사진이 없다 |
| Kaggle, 정답이 확실한 swap | 라벨 교환 | 각인으로 정답이 분명하고 Kaggle 사진은 귀하다 |

## 3. 결과

### 3-1. 이미 아는 오류는 잡혔나

val 오분류 5건 모두 잡혔다. 위치 오류 3건은 위치 검수 1등급, swap 2건은 클래스 검수 1등급이다.

### 3-2. 위치 검수

| 등급 | 의심 bbox | 오류 | 정상 (오탐) |
| --- | ---: | ---: | ---: |
| 1 | 59 | 42 | 17 |
| 2 | 31 | 0 | 31 |
| 3 | 45 | 10 | 35 |
| 합계 | 135 | **52** | 83 |

- 오류 52개(사진 48장) 중 train 36개, val 16개
- 가장 흔한 형태는 **bbox 밀림** (bbox 크기는 맞는데 알약 반쯤 옆에 있음). 다음은 다른 알약 위에 bbox(10개)
- 오탐 원인: 붙어 있는 알약이 한 덩어리로 잡힘, 파란 알약(K-005391, K-031885)을 알약 영역으로 못 찾음, 그림자

### 3-3. 클래스 검수

| 등급 | 의심 crop | 오류 | 정상 (오탐) |
| --- | ---: | ---: | ---: |
| 1 | 16 | 16 | 0 |
| 2 | 19 | 10 | 9 |
| 합계 | 35 | **26** | 9 |

- 오류 26개 중 19개는 위치 검수에서 이미 오류로 판정한 사진이다 (bbox가 다른 알약이나 빈 곳에 있으니 crop도 다른 클래스로 보임)
- **클래스 검수에서만 찾은 오류 7개**

| 사진 | 내용 | 조치 |
| --- | --- | --- |
| Kaggle `K-003483-025367-027733-035206_..._75` (val) | 트윈스타(각인 A1) ↔ 아토젯(각인 337) 서로 바뀜 | 라벨 교환 |
| AI Hub `K-006835-019881-020004-023319_..._75` (train) | 지르텍(흰 Z/Z) ↔ 이튼큐(주황 CKD) 서로 바뀜 | 이미지 제외 |
| AI Hub `K-005000-018357-022074_..._70` (train) | 비유피-4 ↔ 리피로우 서로 바뀜 (두께로 판단) | 이미지 제외 |
| AI Hub `K-011220-016232-027733-031885_..._90` (train) | 리피토(흰 ATV) 자리에 다른 알약("203 Kowa") | 이미지 제외 |

- 오탐 9개: 같은 조합에 오류 사진이 있으면, 멀쩡한 사진이 그 오류 crop과 비교되며 점수가 나빠진다

### 3-4. 데이터 v2에 적용할 조치

`merge_label_audit.py`가 두 검수의 오류를 합쳐 `label_actions.csv`(crop마다 한 줄)를 만든다.

| 조치 | 사진 | crop | train | val |
| --- | ---: | ---: | ---: | ---: |
| 이미지 제외 | 49 | 188 | 134 | 54 |
| bbox 제외 | 2 | 2 | 1 | 1 |
| 라벨 교환 | 1 | 2 | 0 | 2 |

- crop 14,988개 → **14,798개** (train 11,990 / val 2,808)
- 제외 후에도 118개 클래스가 모두 val에 남는다. train이 가장 적은 클래스는 K-003483 (33개, 변화 없음)
- 클래스별 감소와 제외 사진 목록은 [`label_audit_summary.md`](label_audit_summary.md)

## 4. 헷갈리는 품목 쌍: 비유피-4정 vs 리피로우정

| | K-005000 비유피-4정 20mg | K-022074 리피로우정 20mg |
| --- | --- | --- |
| 모양 · 색 | 흰 원형 | 흰 원형 |
| 각인 | 앞 "20" / 뒤 없음 | 앞 "LPL" / 뒤 "20" |
| 두께 | 3.43mm | 4.55mm |

- 비유피-4 crop 191개는 모두 "20" 면이다
- 리피로우 crop 130개 중 13개가 "20" 면(뒷면)이다. 그중 10개는 비유피-4가 없는 조합 사진이라 진짜 리피로우다. 그래서 "20"이 보인다고 비유피-4로 다시 나누지 않는다
- "20" 면만 보이면 두께(옆면 띠)로만 구분된다. 리피로우 뒷면 데이터가 적어(10%) 분류기가 "20 = 비유피-4"로 외웠을 수 있으므로, 탐지기 연결 후 혼동 쌍으로 따로 확인한다

## 5. 한계

- **코드가 고른 후보만 사람이 봤다.** 의심 점수가 낮은 crop(위치 14,853개, 클래스 14,953개)에 남은 오류는 확인하지 못했다. 특히 조금만 밀린 bbox는 3등급 기준(`match_iou` < 0.6)에 걸리지 않을 수 있다
- **같은 그룹 비교가 안 되는 crop이 있다.** 같은 조합의 다른 각도 사진이 없거나 그 사진에 같은 클래스가 없는 crop 3,807개는 교차 검증 예측으로만 검사했다
- **클래스 검수의 embedding은 오류가 섞인 데이터로 학습한 `best.pt`에서 나왔다.** 데이터 v2로 다시 학습한 모델로 한 번 더 검사하면 남은 오류를 더 찾을 수 있다
- 판정은 검수 그림(원본의 절반 크기)을 눈으로 보고 했다. 경계 사례(조금 잘림, bbox가 큼)는 사람마다 다를 수 있다
