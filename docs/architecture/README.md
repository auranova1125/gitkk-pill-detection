# 아키텍처 문서

프로젝트 전체 구조, 공통 모듈, 실행 진입점과 리팩터링 결정을 기록한다. 개별 모델의 구현 계획이나 데이터 입력 계약은 기존 `docs/` 문서에 유지하고, 여러 모델과 파이프라인에 영향을 주는 결정만 이 폴더에 작성한다.

| [프로젝트 구조 리팩터링 계획](project_structure_refactor_plan.md) | 계획 | 멘토 피드백을 반영한 목표 구조, 단계별 작업과 검증 기준 |

## 작성 원칙

- 현재 구조, 목표 구조와 보류 범위를 구분한다.
- 실제 구현과 달라진 계획은 즉시 수정하고 결정 기록에 남긴다.
- 큰 구조 변경은 단계별 검증과 독립 커밋을 전제로 한다.
- 모델별 입력 계약과 checkpoint 호환성을 깨는 변경은 별도로 표시한다.
- 완료된 문서는 삭제하지 않고 상태와 후속 문서 링크를 갱신한다.
